# Codex and shared adapter runtime

This directory contains the dependency-free Node REST client used by the non-Claude adapters. It reads approved canonical context and can submit pending proposals or checkpoints. It does **not** alter Codex native memory.

## Runnable locally

Requirements: Node 20+ and the Hub on loopback.

```bash
export MEMORY_HUB_USER_ID="user-1"
export MEMORY_HUB_PROJECT_ID="project-a"
export MEMORY_HUB_PLATFORM="codex"
export MEMORY_HUB_URL="http://127.0.0.1:8787"

node bin/hub.mjs context --query "database"
printf '%s' "User prefers concise answers" | node bin/hub.mjs propose
```

The proposal command above is a dry-run and does not print its content. To submit a pending proposal, set `MEMORY_HUB_WRITE_ENABLED=1` and add `--send`. Automatic hooks never set `explicit_user_fact`; proposals remain pending for review.

Scope comes only from `MEMORY_HUB_USER_ID` and `MEMORY_HUB_PROJECT_ID`. The CLI rejects scope flags. Non-loopback Hub URLs must use HTTPS. Known credential patterns are blocked locally, upstream error bodies are not printed, and projection-derived metadata is rejected.

The shared runtime prefers `MEMORY_HUB_TOKEN_FILE` over the compatible `MEMORY_HUB_TOKEN` value and never logs either secret. With neither set, it automatically reads the private token generated by the desktop app from `~/Library/Application Support/MemoryHub/hub-token` (macOS), `%APPDATA%\MemoryHub\hub-token` (Windows), or `${XDG_CONFIG_HOME:-~/.config}/MemoryHub/hub-token` (Linux). Token files must be non-symlink regular files no larger than 8 KiB and, on POSIX, mode `0600` or stricter. This behavior is shared by Codex, Qoder, Grok Build, and OpenClaw.

Run tests:

```bash
npm test
```

## Hook templates

`hooks/read-only.example.json` injects approved context at `SessionStart` and `UserPromptSubmit`. Replace the absolute path, merge it into the user-level `~/.codex/hooks.json`, enable hooks in Codex configuration, review the command, and approve hook trust. User-level configuration is recommended because plugin-local hook discovery has varied by Codex release.

`hooks/auto-checkpoint.example.json` is optional. Merge it only after enabling `MEMORY_HUB_WRITE_ENABLED=1`; it writes bounded session checkpoints, not canonical memory proposals. Hook failures are fail-open and emit only a generic warning code.

The MCP TOML is **template only**. The current backend deliberately returns `mcp_transport_not_installed` at `/mcp`; do not add it until a public/authenticated Streamable HTTP MCP bridge exists. Codex MCP launchers are documented in the [official Codex repository](https://github.com/openai/codex).

## Public interface

- `context`: approved canonical context only; no target projection is requested.
- `propose`: pending proposal; stdin only; dry-run unless explicitly enabled.
- `checkpoint`: session summary; stdin only; dry-run unless explicitly enabled.
- Hook injection frames retrieved text as quoted reference data so stored text cannot masquerade as runtime instructions.
